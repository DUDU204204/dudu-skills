# Sales Script Builder - בניית תסריט מכירה

## מה הסקיל עושה
מייצר תסריט שיחת מכירה שלם ומוכן לעבודה - לא עקרונות אלא נוסחים מילה-במילה - מותאם למוצר, לקהל, למקור הליד ולחום שלו, בנוי לסגירה באותו היום.

## בסיס הידע (סדר הקריאה)
1. `00-מתודולוגיות/מכירות/תבנית-תסריט.md` - **התבנית** (השלם-את-החסר) - זה השלד שממלאים
2. `00-מתודולוגיות/מכירות/התאמת-תסריט-למקור-ליד.md` - איך המקור משנה את הפתיח, האורך והיעד
3. `00-מתודולוגיות/מכירות/METHOD.md` - מבנה השיחה המלא
4. `00-מתודולוגיות/מכירות/טיפול-בהתנגדויות.md` - מסלולי ההתנגדויות שמוטמעים בתסריט
5. `00-מתודולוגיות/מכירות/סגירה-באותו-היום.md` - עיצוב הדחיפות, הסגירה וה-post-sell
6. `00-מתודולוגיות/מכירות/מסגרות-העל.md` - להעמקה נקודתית לפי הצורך

## קלט נדרש (לאסוף לפני הכתיבה)
| שדה | מאיפה |
|---|---|
| המוצר וההצעה (מחיר, תשלומים, בונוסים, אחריות, deadline) | דודו / תיקיית הלקוח / דף המכירה |
| האווטאר (כאב, פחד, רצון, שפה) | מסמך מחקר-אווטאר של הפרויקט אם קיים |
| מקור הליד + חום | דודו (וובינר חי? ריפליי? דף נחיתה? קר? הפניה?) |
| מי המוכרים (ניסיון, סגנון) | דודו |
| נתוני שיחות אמיתיות אם קיימים | ניתוחי `/sales-call-analysis` קודמים + `_infra/sales_expert/data/sales.db` |

חסר משהו קריטי? לשאול את דודו לפני, לא להמציא.

## שלבי העבודה
1. **טעינת הידע + הקלט.** אם יש ניתוח שיחות קודם לאותו מוצר - הוא זהב: ההתנגדויות האמיתיות והשפה האמיתית של הקהל משם.
2. **בחירת קונפיגורציה** לפי מטריצת מקור-הליד: פתיח, אורך יעד, יעד שיחה (סגירה מלאה/פגישה), רמת אגרסיביות.
3. **מילוי התבנית** - כל שלב עם נוסחים מלאים בעברית מדוברת, כולל:
   - פתיחה + חוזה מקדים (מסגרת "היום מחליטים")
   - אבחון קצר + שאלות כאב והשלכה (NEPQ)
   - פיצול מסלולים אם הקהל דו-גוני (למשל: מנוסה מול לא-מהתחום)
   - הצגת הצעה + מחיר (עם עוגן), מסלולי ההתנגדויות הצפויות למקור הזה
   - סגירה + שתיקה, גיבוי takeaway, מנגנון תשלום
   - Post-sell: הודעת חיזוק + נכס לבן/בת זוג
4. **בקרת איכות** - להריץ את ה-checklist שבסוף תבנית-תסריט.md; אחר כך מעבר סופרוויזר (`/copy-supervisor` על נוסחי הקופי אם התסריט לקוח-פונה).
5. **תוצר:** Google Doc מעוצב (RTL, Assistant) בתיקיית הלקוח ב-Drive דרך `_infra/html_to_gdoc.py` + עותק md בתיקיית הפרויקט. בקופי אסור em dash - רק "-".

## כללים
- כל נוסח חייב להישמע כמו ישראלי בטלפון, לא כמו מסמך.
- דחיפות רק אמיתית (deadline/מחיר/בונוס שקיימים באמת) - בלי פייק.
- תרחישים ≠ סיפורים אישיים של הלקוח (משמעת עובדות בקופי בגוף ראשון).
- תסריט חדש לנכס קיים = לוודא שוויון-צנרת (לינקים, מחירים, שמות) מול מה שבאוויר.

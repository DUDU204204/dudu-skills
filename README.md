# ערכת הסקילים

> 16 סקילים ל-Claude Code, בעברית, לבעלי עסקים - תוכן ושיווק, וידאו וכתוביות, תמלול, מכירות ותמונות.
> נבנו בעבודה יומיומית אמיתית, ונוקו מכל מידע אישי לפני שיצאו לכאן.

**סקיל** הוא קובץ טקסט אחד שמלמד את הבינה איך אתה עושה משהו שחוזר. במקום להסביר מחדש בכל פעם -
כותבים פעם אחת, וקוראים לזה בשם: `/copy-supervisor`, `/transcribe`, `/reel-critic`.

---

## התקנה

```bash
git clone https://github.com/DUDU204204/dudu-skills.git
cd dudu-skills
./install.sh          # מעתיק ל-~/.claude/skills/
```

או ידנית: להעתיק את התיקיות מ-`skills/` אל `~/.claude/skills/`.

**בדיקה:** פתח שיחה חדשה בקלוד קוד וכתוב `/` - הסקילים אמורים להופיע ברשימה.

## מה צריך בשביל מה

רוב הסקילים עובדים מיד. אלה שדורשים משהו:

| סקיל | דורש |
|---|---|
| `/transcribe` | מודל מקומי (הורדה חד-פעמית, ~3GB) - ההוראות בתוך הסקיל |
| `/hebrew-captions` · `/video-editor` · `/reel-*` | `ffmpeg` (מק: `brew install ffmpeg`) + פונט Assistant |
| `/nano-banana` · `/gpt-image` | מפתח API של הספק, ב-`~/.config/` עם הרשאה 600 |
| `/browser-image-gen` | Chrome עם דיבאג מרוחק + מנוי פעיל |

## איך משתמשים בזה נכון

1. **הסקיל הוא נקודת התחלה, לא תשובה סופית.** הוא יודע מה עובד באופן כללי; הוא לא יודע למה
   *הלקוח שלך* קנה בפעם האחרונה. את זה אתה מכניס.
2. **תוצאה לא טובה = מעדכנים את הסקיל, לא רק את התוצר.** אמור לבינה: "התוצאה חסרה X. תעדכן את
   הסקיל כך שזה לא יקרה שוב, ותראה לי את השינוי". הסקיל מתעבה מצלקות.
3. **כשהצטברו 5-6 חוקים משלך** - מחלצים אותם לקובץ שיטה משלך, והסקיל רק מפנה אליו. ככה סקיל
   שני משתמש באותה שיטה בלי להעתיק אותה.
4. **סקיל שכותב + סקיל שבודק.** כמעט כל סקיל כתיבה כאן מסתיים בקריאה ל-`/copy-supervisor`.
   זה לא קישוט - זה מה שמונע חזרה על אותן שגיאות.

סקילים שקשורים ללקוחות ספציפיים, לכספים או למערכות פרטיות - הם נשארו בבית. מה שכאן הוא
המתודולוגיה, לא הנתונים.
